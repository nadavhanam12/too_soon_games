# PublishGamesPipeline: מהמשחק המוכן להפצה

פקודה אחת, `/launch-game <GameId>`, מריצה את כל השלבים לפי הסדר. אחרי כל שלב היא עוצרת, מראה את התוצרים
בצ'אט, ומחכה לאישור או לתיקון. הרקע וההחלטות: [docs/MARKETING.md](../GamesTemplate/docs/MARKETING.md),
[docs/MARKETING-BUILD-PLAN.md](../GamesTemplate/docs/MARKETING-BUILD-PLAN.md), והפלייבוק v2.1.

## שני חלקים

**הכנה:** רצה לפני שהמשחק מופץ, ולא יוצא ממנה כלום החוצה. כל התוצרים נשמרים מקומית.
**הפצה:** כל פעולה שמפרסמת, שולחת או מוציאה כסף. כל אחת מחכה לאישור מפורש בצ'אט, גם אם כל ההכנה אושרה.

הפרסום של המשחק עצמו לאתר (`/publish-game`) קורה בין ההכנה להפצה, ואינו חלק מהפייפליין הזה.

## איפה הכל נשמר

```
Games/<GameId>/launch/
  state.json        ← איזה שלב רץ, אושר או נכשל (הפייפליין ממשיך משם)
  videos/           ← MP4, GIF, תמונות שער (לא ב־git: כבדים)
  copy.json, press/, paid.json
  private/          ← כתובות מייל ושמות של כתבים ויוצרים. לא ב־git, לעולם
  log.jsonl         ← כל פעולת הפצה: מה, איפה, מתי, לינק
```

רשימת ההסרה משותפת לכל המשחקים: `PublishGamesPipeline/private/suppression.csv` (לא ב־git).

## מצב ניסיון

`/launch-game <GameId> --dry-run`: כל ההכנה רצה כרגיל, ושלבי ההפצה רק מדפיסים מה היו עושים.
כך בודקים את הפייפליין על משחק קיים בלי שיצא משהו החוצה.

## קבצים

```
PublishGamesPipeline/
  README.md
  config.json             ← שולח, כתובת דואר, הדגלים המשפטיים (מייל קר כבוי עד בדיקת עו"ד)
  lib/state.mjs           ← קריאה וכתיבה של state.json

  skills/launch-game/     ← הסקיל המרכזי (עטיפה ב־.claude/skills/launch-game)
```
