# הקמת Cloudflare (פעם אחת)

**סטטוס: החלטה.** **Workers Paid (5$ לחודש) מ־2026-11-18** (החלטה 87). עד אז המסלול החינמי.

## מה אתה עושה (דברים שדורשים חשבון, זהות או תשלום)

1. **פתיחת חשבון:** https://dash.cloudflare.com/sign-up עם אימייל וסיסמה. אין צורך בכרטיס.
   מומלץ להפעיל אימות דו־שלבי (Profile → Authentication).
2. **Node.js:** אם לא מותקן, להתקין את גרסת ה־LTS מ־https://nodejs.org (כולל npm).
3. **התחברות של הכלי לחשבון:** בטרמינל, מתיקיית הפרויקט:
   ```bash
   npx wrangler login
   ```
   נפתח דפדפן, מאשרים, סוגרים. מרגע זה הפקודות רצות בשמך מהמחשב הזה.
4. **Account ID:** בלוח הבקרה, Workers & Pages, בצד העמוד מופיע "Account ID". להעתיק לשורת
   `CF_ACCOUNT_ID` בקובץ `GamesTemplate/server-and-data/worker/.dev.vars` (מותר גם בצ'אט, הוא לא סוד).
5. **API Token לקריאת האנליטיקה:** My Profile → API Tokens → Create Token → Create Custom Token.
   שם: `toosoon-analytics`. הרשאה אחת: **Account · Account Analytics · Read**. Account Resources:
   החשבון שלך. Continue → Create Token. להעתיק לשורת `CF_API_TOKEN` ב־`.dev.vars`. **לא לשלוח בצ'אט.**
   בלי זה הכל עובד חוץ ממסך האדמין, שיציג "אנליטיקה לא זמינה".
6. **Node.js:** נדרש 22 ומעלה (wrangler). בוצע 2026-11-15: Node 26.13 LTS הותקן דרך `winget install OpenJS.NodeJS.LTS`,
   ונעיצת wrangler 4.80 הוסרה (`^4.162`). אחרי שדרוג wrangler מסד ה־D1 המקומי מתחיל ריק: `npm run migrate:local` בתיקיית השרת
   לפני `npm run dev`.
7. **(מאוחר יותר, כשתרצה)** דומיין: Domain Registration → Register, או העברת דומיין קיים.
   דורש תשלום. עד אז הכתובת היא `https://<project>.pages.dev`.
8. **אמצעי תשלום ו־Workers Paid:** ראה "מעבר ל־Workers Paid" למטה. מומלץ לפני כל השקה גדולה.

## מה האוטומציה עושה מכאן (סקיל `/deploy-server`, הפעלה ראשונה)

- `wrangler d1 create toosoon` → יוצר את מסד הנתונים, כותב את ה־id ל־`wrangler.toml`.
- `wrangler d1 migrations apply` → יוצר את הטבלאות.
- `wrangler secret put ADMIN_KEY` → מפתח אדמין אקראי (נשמר אצלך ב־`.env.local`, לא ב־git).
- `wrangler deploy` → ה־Worker עולה לכתובת `https://api.<account>.workers.dev`.
- `wrangler pages project create toosoon-games` → פרויקט ה־Pages, כתובת `https://toosoon-games.pages.dev`.
- Analytics Engine: נוצר אוטומטית מה־binding ב־`wrangler.toml`, אין מה להגדיר.
- Rate limiting: binding ב־`wrangler.toml`, אין מה להגדיר.

## מעבר ל־Workers Paid (5$ לחודש): מדריך

**בוצע 2026-11-18.** הסעיפים למטה נשארים כתיעוד, וסעיף 3 (התראות) הוא מה שצריך לבדוק שהוגדר.

**מתי:** לפני כל השקה שצפויים בה יותר מ־1,500 שחקנים ביום. במסלול החינמי הגבול הוא בערך 2,000, ואין התראה כשהוא נגמר.

### 1. השדרוג (5 דקות, בלוח הבקרה)
1. https://dash.cloudflare.com → בחירת החשבון.
2. **Workers & Pages** בתפריט השמאלי → **Plans** (או "Compare plans").
3. **Workers Paid** → **Purchase** / Upgrade. מזינים כרטיס אשראי (אתה מזין, לא Claude).
4. החיוב: 5$ לחודש מינימום, כולל את כל המכסות בטבלה למעלה. חריגה מחויבת לפי השימוש (המחירים בטבלה).
5. המגבלות היומיות של D1 ו־Workers נעלמות תוך דקות. לא צריך לשנות קוד ולא לפרוס מחדש.

### 2. לבדוק שזה עבד
- Workers & Pages → Plans מציג **Workers Paid**.
- Workers & Pages → D1 → `toosoon` → Metrics: אין הודעה על "daily limit".
- תגיד ל־Claude "תבדוק את השרת": ירוץ smoke מול השרת החי.

### 3. תקרת הוצאה והתראות (הוגדר 2026-11-18)
**מוגדר:** Billing → Spend Management: תקרה של 2$ ל־Workers ו־2$ ל־Durable Objects, ושתי התראות "Billing budget alert".
- התקרה סופרת רק חריגה מעבר למה שכלול ב־Paid (10M בקשות, 30M מילישניות CPU בחודש), בלי ה־5$ של המנוי. החשבון המקסימלי
  הצפוי: 5$ + 2$, ועוד מעט כי החסימה מתעכבת בכמה דקות.
- בהגעה לתקרה כל ה־Workers בחשבון נחסמים עד תחילת תקופת החיוב הבאה (ה־API ועמודי המשחקים; שגיאה 1103). קבצים סטטיים ממשיכים.
- התקרה לא כוללת D1 ו־Analytics Engine. הם נקראים רק דרך ה־Worker, והקריאה היקרה (הדירוג) מוגבלת: 120 קריאות לוח ומונה לדקה
  ל־IP, ומטמון של 10 שניות לכל ניקוד.

### 3א. התראות על חיוב (הרקע: אין תקרה על D1)
ב־Paid אין עצירה כשעוברים את המכסה, יש חיוב. כדי שלא תופתע:
1. **Notifications** (בתפריט החשבון) → **Add** → **Usage Based Billing** → מוסיפים את האימייל שלך.
   בוחרים מוצר (Workers, D1) וסף. הצעה: התראה על 2M קריאות D1 ביום ועל 500K בקשות Worker ביום. בסדר הגודל הזה יום כזה עולה סנטים.
2. **Billing → Billing notifications**: התראה כשהחשבונית החודשית עוברת 20$.
3. (אופציונלי) Notifications → **Workers** → התראה על שיעור שגיאות, כדי לדעת אם ה־API נשבר ביום ההשקה.

### קיבולת בשיא (Paid): נמדד בבדיקת עומס, 2026-11-18
עותק זמני של ה־API (Worker ו־D1 נפרדים על workers.dev, בלי הגבלות IP, נמחקו בסוף) עם 20,000 ניקודים. כל "ריצה" היא מה שלקוח
שולח בסוף משחק: אצוות אירועים, ניקוד, לוח עם userId, מונה. 15 שניות בכל קצב, ממחשב אחד בבנגקוק.

| ריצות בשנייה | ריצה שלמה, חציון / p95 | שגיאות |
|---|---|---|
| 10 | 281ms / 319ms | 0 |
| 25 | 280ms / 316ms | 0 |
| 50 | 291ms / 366ms | 0 |
| 100 | 414ms / 694ms | **כשליש מבקשות הניקוד והלוח: 500** |

השגיאה ב־100: `D1_ERROR: D1 DB is overloaded. Too many resources consumed within a 10 second window.` ל־D1 יש תקציב משאבים
לחלון של 10 שניות, ומי שמנצל אותו הוא חישוב הדירוג (`COUNT(*) WHERE score > ?`), שקורא בממוצע חצי מהטבלה. אירועים ומונה לא נכשלו.
כשהמסד עמוס, גם כתיבות ה־D1 של האירועים (users, players) נכשלות ברקע; האירועים עצמם ממשיכים ל־Analytics Engine.

**הגבול כנוסחה:** בערך מיליון שורות דירוג בשנייה מחזיקות, שניים לא. בבדיקה היו שתי שאילתות דירוג לריצה (ניקוד ולוח). מאז החלטה 89
יש אחת (הלוח לא סופר), ולכן **ריצות בשנייה ≈ 2,000,000 חלקי מספר הניקודים במשחק**. הכפלה מחושבת, לא נמדדה שוב:
| ניקודים במשחק | ריצות בשנייה בלי שגיאות (הערכה) |
|---|---|
| 5,000 | כ־400 |
| 20,000 | כ־100 (נמדד 50 עם שתי ספירות) |
| 50,000 | כ־40 |
| 100,000 | כ־20 |

יום ויראלי של 50,000 שחקנים מגיע לשיא של כ־10 ריצות בשנייה, כשבטבלה כבר עשרות אלפי ניקודים: קרוב לגבול. לכן דירוג בלי
COUNT (BACKLOG) הוא תנאי להשקה גדולה, לא שיפור עתידי. בשרת האמיתי (דומיין מותאם) הדירוג בלוח נשמר במטמון לפי ניקוד, וב־workers.dev
אין מטמון, כך שהבדיקה מעט פסימית לגבי הלוח; הדירוג בשליחת ניקוד תמיד מחושב.
Workers, Pages ו־Analytics Engine לא הגבילו בשום שלב.

### הגבול הבא (גם ב־Paid)
חישוב הדירוג (`SELECT COUNT(*) ... WHERE score > ?`) קורא את כל השורות שמעל הניקוד של השחקן, פעם בשליחת ניקוד ופעם בצפייה
בלוח. העלות גדלה עם מספר הניקודים המצטבר של המשחק. במשחק עם 100,000 ניקודים ו־20,000 ריצות ביום זה כ־2 מיליארד קריאות ביום,
כלומר כ־35$ בחודש מעבר ל־25B הכלולים. כשמשחק עובר 50,000 ניקודים: לעבור לדירוג לפי טבלת סכומים לפי טווחי ניקוד (BACKLOG).

## חירום
- **שחזור נתונים:** `wrangler d1 time-travel restore toosoon --timestamp=<ISO>` (7 ימים אחורה בחינמי, 30 ב־Paid).
- **גיבוי יומי:** משימה מתוזמנת ב־Windows ("TooSoonGames D1 backup", כל יום ב־04:00, או בהדלקה הבאה של המחשב) מריצה את
  `server-and-data/backup/export.sh` → `backups/toosoon-<date>-remote.sql`, ושומרת את 30 האחרונים. יומן: `backups/schedule.log`.
  הקמה מחדש: `powershell -ExecutionPolicy Bypass -File server-and-data/backup/schedule-daily.ps1`. דורש `wrangler login` בתוקף.
- **ייצוא ידני:** `bash server-and-data/backup/export.sh`.
- **חזרה לגרסת שרת קודמת:** Workers → api → Deployments → Rollback (או `wrangler rollback`).

חשבון חדש בלי תת־דומיין: ההעלאה מצליחה אבל נגמרת ב־`register a workers.dev subdomain`, ולשרת אין כתובת.

`https://toosoon-api.toosoon121234.workers.dev` (רשומה ב־`studio.json` → `apiBase`). השם מופיע רק בכתובת ה־API.

## הדומיין toosoongames.app (2026-11-15)

ה־DNS של הדומיין ב־Cloudflare (nameservers odin/christina.ns.cloudflare.com), באותו חשבון.
- **API:** `api.toosoongames.app`, דומיין מותאם של ה־Worker (`routes` ב־`wrangler.toml`, `custom_domain = true`). Cloudflare יוצר
  את רשומת ה־DNS והתעודה לבד בפריסה. שים לב: ברגע שיש דומיין מותאם, כתובת ה־workers.dev מפסיקה לענות (שגיאה 1042),
  לכן `studio.json.apiBase` חייב להצביע על הדומיין.
- **אתר:** דומיין מותאם לפרויקט Pages, פעם אחת בלוח הבקרה: Workers & Pages → toosoon-games → Custom domains →
  Set up a custom domain → `toosoongames.app` (ושוב ל־`www.toosoongames.app`). Cloudflare מוסיף את רשומות ה־CNAME לבד.
  ל־wrangler אין פקודה לזה. אחרי ההפעלה: `studio.json.publicBase` → `https://toosoongames.app` ופרסום מחדש של האתר
  ושל כל המשחקים (ה־OG והקישורים נבנים מ־publicBase).
- `ALLOWED_ORIGINS` ב־`wrangler.toml` כולל את שני הדומיינים ואת pages.dev.
