# פרסום משחק ופורטל המשחקים

**סטטוס: הצעה** (2026-11-14). מתאר איך משחק חדש עולה לדומיין ואיך הפורטל נבנה.

## מבנה הכתובות

```
https://toosoon.games/                 פורטל: כל המשחקים, חדש למעלה
https://toosoon.games/chip-drop/       משחק (slug = GameId באותיות קטנות עם מקפים)
https://toosoon.games/chip-drop/og.png תמונת התצוגה המקדימה של המשחק
https://toosoon.games/privacy          פרטיות ותנאים
https://api.toosoon.games/v1/...       השרת (Worker)
```
עד שיש דומיין: `https://toosoon-games.pages.dev/...` ו־`https://api.<account>.workers.dev/...`.
החלפה לדומיין = שני שדות הגדרה (`publicBase`, `apiBase`), בלי שינוי קוד.

## איך זה עובד מקצועית

**Pages = אתר סטטי אחד, כל משחק תיקייה.** פרויקט Pages יחיד מקבל תיקיית `dist/` ומגיש אותה מה־CDN
של Cloudflare בכל העולם. ה־build מייצר:
```
dist/
  index.html            הפורטל (נוצר מ־games.json)
  privacy/index.html
  chip-drop/index.html  המשחק, קובץ אחד
  chip-drop/og.png
  chip-drop/assets/...  אם יש (אודיו)
  _headers              cache: html קצר (60 שניות), assets ארוך
```
**חיבור הדומיין (פעם אחת):** Pages → Custom domains → `toosoon.games` + `www`. כיוון שהדומיין
ב־Cloudflare, רשומות ה־DNS וה־HTTPS נוצרים לבד תוך דקות. ל־API: Worker → Settings → Domains →
`api.toosoon.games`.

**גרסאות ושחזור:** כל פריסה נשמרת. Pages → Deployments → Rollback מחזיר את כל האתר לגרסה קודמת
בלחיצה. פריסה היא אטומית: אין רגע שבו חצי מהקבצים חדשים.

## שתי דרכים לפרוס, ומה מומלץ

| | A: מהמחשב (`wrangler pages deploy`) | B: מחובר ל־GitHub |
|---|---|---|
| איך | הסקיל בונה ומעלה את `dist/` | push ל־`main` → Cloudflare בונה ומפרסם לבד |
| זמן עד לאוויר | כדקה | 1-2 דקות |
| תצוגה מקדימה לפני פרסום | ידנית (`wrangler pages dev`) | **כל branch מקבל כתובת משלו** `abc123.toosoon-games.pages.dev` לבדיקה בטלפון לפני merge |
| דורש | wrangler login | הריפו ב־GitHub + אישור חד־פעמי |
| מתאים ל | התחלה | שגרה של 10 שעות |

**המלצה:** להתחיל ב־A (אין תלות בשום דבר חוץ מ־login), ולעבור ל־B אחרי המשחק הראשון. ב־B זרימת
10 השעות נראית כך: branch `game/chip-drop` → פריסות תצוגה מקדימה אוטומטיות לכל commit → בודקים
בטלפון מהקישור → merge ל־`main` → באוויר. גם ב־B הסקיל עדיין רץ (בדיקות, build, רישום בשרת),
רק ההעלאה עצמה עוברת ל־GitHub.

## זרימת פרסום משחק חדש (`/publish-game <GameId>`)

0. **תמונות שיתוף:** `og.png` ו־`cover.png` בתיקיית `assets/` של המשחק. חסרות? `make-assets.mjs` מייצר אותן ממסך
   הפתיחה (חוק 21א). בלי og.png הכרטיס בווצאפ ריק, וזה הרושם הראשון של המשחק.
1. **בדיקות:** כלי הבאגים. אדום עוצר.
2. **רישום בפורטל:** אם המשחק לא ב־`games.json`, מוסיף שורה: slug, שם, שורת תיאור, תמונה, תאריך
   האירוע, קהל, סטטוס `live`.
3. **רישום בשרת:** `PUT /v1/games/<id>` עם מפתח אדמין: `maxScore`, `minDurationS`, שם. **השרת לא
   צריך פריסה מחדש בשביל משחק חדש.** זה חשוב: השרת משתנה לעיתים רחוקות, משחקים כל שבוע.
4. **build:** כל המשחקים + הפורטל ל־`dist/`. גרסת המשחק עולה.
5. **פריסה:** `wrangler pages deploy dist` (או push, בשיטה B).
6. **אימות:** פתיחת הקישור הציבורי, `GET /v1/games/<id>/board` עונה, OG נראה תקין בכלי של
   Cloudflare/Facebook debugger. הסקיל מדפיס את הקישור ואת רשימת הבדיקות הידניות מחוק 23.

משחק קיים שמתקנים: אותה זרימה, בלי שלבים 2 ו־3.

## הפורטל

- **מקור אמת:** `games.json` בשורש התבנית. שורה לכל משחק. ה־build מייצר ממנו את `index.html`.
- **מה מציג:** כרטיס לכל משחק: תמונה, שם, שורת תיאור, תאריך האירוע, ו־"N שחקנים" (מ־API,
  נקודת קצה אחת `GET /v1/games/count` לכל המשחקים, cache דקה). הכי חדש למעלה. משחקים `archived`
  למטה עם תאריך ברור, עדיין ניתנים למשחק.
- **שפה:** כרטיסים בשפת המשחק. סדר: קודם המשחקים בשפת הדפדפן, אחריהם השאר. בלי מתג שפה בשלב זה.
- **בלוק "המשחק הבא":** כפתורי עקבו אחרינו, כמו במסך הקהילה.
- **מתוך משחק לפורטל:** במסך הקהילה שורה "עוד משחקים שלנו" → `/`. זה הגרעין של "המלצות למשחקים
   נוספים" משקופית 08, בעלות אפסית.
- **SEO:** כותרת ותיאור לכל משחק, `sitemap.xml` שנוצר ב־build, `robots.txt`.
- **קישור קבוע:** ה־slug לא משתנה אחרי פרסום (חוק 5). שינוי שם תצוגה מותר, שינוי כתובת לא.
